# Polish for OBS

Written by [Taki Sadik](../../about) · Last updated 2026-11-24 · 12 min read

Free, open-source beauty, makeup and camera effects for OBS Studio on macOS, with no watermark

## Overview

Streamers and people on video calls want the same camera touch-ups phone apps have: smoother skin, a little makeup, better colour, a blurred or replaced background. On OBS for Mac the usual answer is a paid plugin that stamps a watermark on your stream until you subscribe. Polish is a free, open-source OBS filter that does those effects on your own Mac, with no account, no upload and no watermark.

It adds one filter to any video source. The filter tracks faces and finds the person in each frame with Apple's Vision framework, which ships with macOS, and applies every effect as a GPU shader in OBS's own effect language. Nothing is downloaded at run time and there are no third-party models: the looks, stickers and backdrops are generated by a script in the repository.

The source code is on GitHub at [TYFSADIK/obs-polish](https://github.com/TYFSADIK/obs-polish), under the MIT licence, with a universal build (Apple silicon and Intel) for OBS 30 and later on macOS 12 and later in [Releases](https://github.com/TYFSADIK/obs-polish/releases).

## What It Does

| Group | Controls | How |
| --- | --- | --- |
| Beauty | Smooth skin, brighten skin, sharpen | An edge-preserving filter limited to skin inside each tracked face; a brightness curve that keeps skin's own colour |
| Face shape | Slim face, bigger eyes | A displacement field from the jaw landmarks and a local zoom on each eye |
| Makeup | Lipstick and blush in any colour, whiter teeth, brighter eyes | A lips and mouth mask drawn from the lip landmarks; blush placed from the cheeks |
| Colour | 17 looks in Portrait, Food, Landscape and Modern groups, with a strength slider; exposure, warmth, saturation, vignette, film grain | A 64-step 3D lookup table per look |
| Background | Blur, solid colour, four built-in backdrops (Studio, Gradient, Bokeh lights, Sunset), your own image, edge softness | Vision's person mask composited on the GPU |
| Stickers | 10: sunglasses, star glasses, crown, flower crown, cat ears, bunny ears, devil horns, halo, hearts, party hat | Placed from the eyes and rotated with the head |
| Compare | A checkbox, and a hotkey you hold | Shows the untouched input, exactly |
| Setup | Tools menu entry, 8 languages | Adds the filter to the selected source or the first camera and opens its settings |

## How It Works

OBS gives a filter its source as a texture once per frame. Polish captures it, then runs only the passes that are switched on, each into an off-screen texture that feeds the next. With everything off, the output is the input pixel for pixel.

Face landmarks and the person mask come from Apple's Vision framework. Reading a full frame back from the GPU would stall rendering, so the filter draws a 384-pixel-wide copy into a staging surface and reads it on the next frame, by which time the copy is finished. A serial background queue runs Vision on it. If the queue is still busy, that frame is skipped; the effects keep using the most recent result, which is also smoothed over time so landmarks do not jitter.

## Build Process, Step by Step

A plugin has to match the libobs it loads into. The build fetches the headers for the exact OBS tag (33.0.3) with a sparse checkout, plus SIMDe, which libobs's maths headers need on Apple silicon. The plugin links with -undefined dynamic_lookup, so libobs symbols resolve against the running OBS and the plugin builds on a machine without OBS installed, including CI. The frontend API (the Tools menu, saving the hotkey) is looked up at run time with dlsym, so the same binary also loads where there is no OBS window.

Before writing any effect, I wrote render-test: a small program that starts the libobs from /Applications/OBS.app with no window, loads OBS's image source and the plugin, runs a picture through the filter for a number of frames, and writes the result as a PNG. It can also ask the filter for its analysis state as JSON. Every change after that was checked by looking at real OBS output, not by reasoning about shaders.

Vision's face landmarks request returns the face contour, eyes, nose and roll. I store the eyes by their position in the image rather than Vision's left and right, resample the jaw to 17 evenly spaced points so every face has the same shape, and blend each new result with the previous one. On the test portrait it finds the face in about 8 ms per frame.

The smoothing pass samples three rings of eight pixels around each pixel and weights each sample by distance and by how similar its colour is, so the eyes, brows and the edge of the face stay sharp while skin texture softens. It only acts where a pixel looks like skin (a soft range in YCbCr) and lies inside an ellipse fitted to the tracked face, and it always keeps a little of the original texture so skin never looks like plastic.

float region = skin_prob(c.rgb) * face_weight(uv);
// 3 rings x 8 samples, weighted by distance and colour difference
float wr = exp(-dot(d, d) / 0.0072);
float3 outc = lerp(c.rgb, smoothed, smooth_amt * region * 0.82);

The first version lifted every channel toward white, and at high settings skin went grey and flat. The fix was to raise luminance along a soft curve and scale the colour by the same ratio, so the balance between red, green and blue, and with it the skin tone, stays put. The test checks it: luminance rises by about 28 levels at full strength while the red-to-blue ratio moves by 0.01.

Six jaw landmarks each carry a small push toward the middle of the face, mostly sideways so the jaw narrows instead of lifting. The shader computes, for every pixel, the falloff-weighted average of the nearby pushes and samples the image from that offset. Eyes get a local zoom inside a radius set from their measured size.

float2 d = w0 * ctl0.zw + w1 * ctl1.zw + ... + w5 * ctl5.zw;
return pos - d / max(w0 + w1 + w2 + w3 + w4 + w5, 1.0);  // an average, never a sum

Lip colour needs the shape of the lips, not an ellipse. When lipstick or teeth whitening is on, the analyzer draws Vision's outer and inner lip outlines into a small two-channel mask with Core Graphics: the lips (outer minus inner, so an open mouth stays uncoloured) and the mouth interior. Lipstick blends the chosen colour in soft light, which keeps the lips' own light and shade. Teeth whitening acts only on bright, unsaturated pixels inside the mouth, so the tongue and gums are left alone. Blush is a soft ellipse on each cheek, placed between the eye and the jaw, multiplied into skin so the texture shows through.

CGContextEOFillPath(lips);   // outer lips, then inner lips: even-odd leaves the opening empty
float3 tinted = soft_light(rgb, lip_color.rgb);
rgb = lerp(rgb, tinted, mask.r * lip_amount);

Vision's person segmentation gives a mask about 384 by 512 pixels. It is uploaded as a texture whenever a new one arrives and composited with an adjustable soft edge. The blur runs at quarter resolution, as a separable Gaussian repeated up to four times, so even a heavy blur costs little.

Each look is a 512 by 512 lookup table (64 tiles of 64 by 64) produced by a Python script from simple operations: white balance, saturation, an S-curve, split toning, and for Lush a boost limited to greens and blues so skin is left alone. They are grouped the way camera apps group them: Portrait, Food, Landscape and Modern. The stickers and the four backdrops are drawn by the same script. Nothing in the repository is third-party art, which keeps the licence simple.

A Tools menu entry adds the filter to the selected source, or to the first camera in the scene, and opens its settings. A hotkey you hold shows the original on every Polish filter at once, and its binding is saved with the scene collection. Labels are translated into English, French, Spanish, German, Portuguese, Chinese, Japanese and Korean, and follow OBS's language setting.

Every push builds the universal plugin on a macOS runner, checks the bundle and its exported module functions, and packages a zip with a double-click installer that copies the plugin into OBS's user plugin folder.

## Testing

The test suite renders a public-domain NASA portrait (Chris Hadfield) through the filter inside real libobs and checks the pixels. All 14 checks pass:

| Check | Result |
| --- | --- |
| Every effect off | Output identical to the input, pixel for pixel |
| Face tracking | 1 face, eyes level and above the chin, about 8 to 12 ms |
| Smoothing | Forehead detail 4.41 to 2.33; background untouched |
| Brightening | Luminance up 28 levels; red to blue ratio 1.63 to 1.64 |
| Face shape | Only pixels near the face change |
| Background blur | Detail behind the subject halved; the face unchanged |
| Solid colour | The background patch comes out pure green |
| Identity look | Within 1 level of the input |
| Mono look | No colour left |
| Sticker | Drawn above the eyes |
| Lipstick | Only pixels around the mouth change, and they get redder |
| Vignette | Corners darker by 48 levels, centre unchanged |
| Built-in backdrop | Background replaced, face unchanged |
| Compare | Identical to the input with every effect on |

Testing found real bugs. The face-shape warp tore the lower face apart: the six control points overlap, and applying their pushes one after another added them up, so a 4-pixel setting moved the chin about 20 pixels. Plotting the landmarks on the photo showed they were right, logging the shader's inputs showed they were right too, and the fix was to average the pushes instead of chaining them. The first contact sheet of looks and stickers showed no effect at all, which turned out to be renders from before the assets existed; the identity-look test had passed anyway, because an identity look changes nothing, which is why the suite now also checks that Mono removes colour. The first smoothing check failed because it measured the whole face box, where eyes and moustache are edges the filter is meant to keep; it now measures forehead skin. The first CI run never started because GitHub had retired the macOS runner image it named. And while adding the new stickers, a fix to the bunny ears did not show up: the build copied the assets into the plugin only when the code was relinked, so a change to an image alone left the old one in place. The copy is now a build step that always runs.

## Challenges and Lessons Learned

Build the harness first. A shader that compiles can still be wrong in ways no one would guess from the code. Rendering inside the real libobs and looking at the output caught every bug on this page.

A test that cannot fail proves nothing. The identity look passed while looks were not being applied at all. Pairing it with a test that must change the image (Mono) closed the gap.

Never wait for the GPU. Reading the analysis copy back one frame late, and dropping frames when Vision is busy, keeps the filter's cost to the shaders alone.

Use what the platform ships. Apple's Vision framework gives face landmarks and person segmentation with no model files to download, license or update. The price is that the plugin is macOS only.

## Limits

- macOS only. Analysis uses Apple's Vision framework. A Windows or Linux version would need another landmark and segmentation model, for example MediaPipe through ONNX Runtime.

- The mask is slightly behind. The person mask is one or two frames older than the picture, so fast movement can show a thin edge.

- One face for shape and stickers. Face shape, blush, eye brightening and stickers follow the largest face; smoothing and lipstick cover up to two.

- Moustaches hide lips. A full moustache can hide part of the upper lip from the lip landmarks, so lipstick only reaches what Vision can see.
