Ground: Seismic & Acoustic Perimeter Mesh

Solar-powered 915 MHz LoRa mesh of ESP32 sensor nodes with ADXL355 accelerometers (and an SM-24 geophone upgrade path) that classify vehicles vs footsteps vs wind at the edge and report signed detections to a common operating picture.

2026 Defence Hardware In Progress

Overview

This build is the land component of the layered domain-awareness picture Canada is assembling in the Arctic. The Canadian Arctic Sensor Suite Initiative aims at persistent surveillance from seabed to space, and the ground layer of that picture is a network of unattended sensors that stay alive for months in harsh conditions and report only what matters. DRDC's Northern Watch demonstration already showed where these systems hurt: not the sensors themselves, but installation, ice, technical failures, and data management.

My mesh is five ESP32 LoRa nodes spread across land I control. Each node reads a seismic sensor, classifies what it feels (vehicle, footsteps, or wind) on the device, and sends only a short signed detection message over the 915 MHz mesh to a Raspberry Pi gateway. Raw waveforms never leave the node - there is no bandwidth for them, and no need. When the gateway is unreachable, nodes buffer and sync later, which is the same store-and-forward discipline the rest of my defence program runs on.

The reason this belongs in a DevOps engineer's portfolio: keeping cheap nodes alive through a Canadian winter, buffering through dead links, signing their output, and fusing them into one trustworthy picture is an infrastructure problem wearing a hardware costume. That is the layer I build.

The design rule is that the mesh carries detections, not data. A signed JSON detection (node id, timestamp, class, confidence, feature summary) is a few dozen bytes - small enough for LoRa's duty-cycle limits, small enough to buffer hundreds of on a node during a gateway outage, and small enough to sign on an ESP32 without breaking the power budget.

How I Built It

01
Node bring-up

Flashed the ESP32 LoRa boards (Heltec V3 / LilyGO T-Beam class) with the Arduino-ESP32 core via esptool.py, using the RadioLib library for the SX1262 radio driver. Region is set to 915 MHz - the North American ISM band; 868 MHz hardware is for Europe and stays out of the build. First milestone was a two-node range check: one node on the bench, one walked down the street, logging RSSI and SNR per packet to find the honest hop distance before designing the mesh topology.

02
Seismic front end

The ADXL355-class MEMS accelerometer sits on the SPI bus (the 355 is SPI-only, which avoids I2C noise issues at speed) and streams at roughly 1 kHz. The sensor couples to the ground through a spike on the enclosure base - coupling quality matters more than sensor price. Firmware windows the samples and extracts features at the edge: RMS amplitude plus spectral band energies from an FFT over each window, so the classifier sees a compact feature vector instead of raw samples.

03
Edge classification

First pass is thresholds: footsteps are short, spiky, and periodic in a walking cadence band; vehicles are sustained, lower-frequency, and grow then fade as they pass; wind is broadband and correlates across sensors differently. That rule-based classifier is already useful and fully explainable. The second pass is a tiny ML model - a small feature-vector classifier trained in Python on labelled recordings I collect on my own land (walking, driving, windy days), converted with TensorFlow Lite Micro / Edge Impulse to run on the ESP32. Only the class and confidence leave the node - never raw seismic or audio streams.

04
Mesh and gateway

Nodes forward detections over the LoRa mesh to a Raspberry Pi gateway wearing a LoRa HAT. When the gateway is unreachable - link down, gateway rebooting, me messing with it - the node appends the signed detection to a local ring buffer in flash and replays on reconnect, oldest first. The gateway side is a small Python service (paho-mqtt client) that validates signatures, deduplicates replayed messages, and republishes to the broker.

05
Power

Each node runs on 18650 cells in protected holders, topped up by a small solar panel through a charge board, inside a weatherproof box with IP65 cable glands for the sensor leads. The firmware sleeps the ESP32 between sample windows and keeps the radio off except for scheduled mesh slots, because the power budget - not the sensor - is what decides whether a node survives a dark, cold week in January.

06
Geophone upgrade path

The two SM-24 geophones and a precision ADC are the sensitivity upgrade: a true geophone picks up vehicle signatures at ranges a MEMS accelerometer cannot. The ADC sits on the same SPI bus pattern as the ADXL355, so the feature pipeline and classifier carry over unchanged - only the front-end driver and the expected detection range differ. The three labelled geophones in the bench photo are staged for exactly this swap.

07
Verify-asset integration

A mesh detection does not trigger anything automatic - it queues a task for a human. The common operating picture shows the detection; I decide whether to send the GPS-denied rover or the thermal SAR drone to look. The human tasks, the machine ferries. That separation is deliberate and it stays in every version of this system.

08
Reporting

Every node publishes signed detections over MQTT to the multi-domain common operating picture, where they fuse with the air and water tracks from the sibling builds. Signing happens on the node before transmission, so a forged or corrupted message is dropped at the gateway before it ever reaches the picture.

Testing & Metrics

The test protocol is built around labelled ground truth I generate myself on land I control:

  • Classification accuracy: scripted passes of each class - me walking known routes, my vehicle driving past at set distances, and logged windy days as the reject class - scored as a confusion matrix per node. Target is high vehicle/footstep separation with wind false alarms driven toward zero before any deployment is called done.
  • Detection range: walk-in and drive-in tests from measured distances, mapping the range at which each sensor front end (ADXL355 vs SM-24 geophone) reliably fires. This is the number that justifies the geophone upgrade, so it gets measured, not assumed.
  • Mesh reliability: packet delivery ratio per hop at the measured node spacing, plus store-and-forward recovery - the gateway is deliberately killed for an interval and the buffered detections must arrive, in order, with no loss, on reconnect.
  • Power endurance: battery voltage and charge state logged through real weather, including cold snaps, to validate the solar + 18650 budget against the sleep schedule.

Results are not published yet - data collection is in progress and the numbers will land on this page with the dataset once the labelled runs are complete.

Legal, Safety & Canada Notes

Radio rules: the mesh transmits on 915 MHz, the North American ISM band, at LoRa-legal power and duty cycle. 868 MHz hardware is for Europe and is not used. Nothing in this build jams, spoofs, or interferes with anyone else's signals.
Placement and privacy: nodes run only on land I control and are never pointed at other people. The seismic and acoustic processing targets machinery and movement signatures - engine rumble, footstep cadence - not speech. Only short class labels and confidence values leave each node; raw waveforms stay on the device.
