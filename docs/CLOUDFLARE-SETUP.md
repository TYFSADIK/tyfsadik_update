# Cloudflare setup for tyfsadik.org

Manual steps I perform in the Cloudflare dashboard (or API). Nothing here runs from the repo. Each section says exactly where to click and what to paste.

## 1. Response headers (Rules, Transform Rules, Modify Response Header)

Create one Transform Rule named `security-headers`, expression `true` (or `http.host eq "tyfsadik.org"`), then add these static headers:

| Header | Value |
|---|---|
| `Strict-Transport-Security` | `max-age=31536000` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |

Do NOT add `includeSubDomains` to HSTS until every subdomain (including `ai.tyfsadik.org`) serves valid HTTPS. Once confirmed, change the value to `max-age=31536000; includeSubDomains`.

### Content Security Policy, report-only first

Add one more header in the same rule:

```
Content-Security-Policy-Report-Only: default-src 'self'; img-src 'self' data:; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline'; font-src 'self'; connect-src 'self' https://cdn.jsdelivr.net; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
```

Why `'unsafe-inline'` appears: `index.html` carries an inline loader script and inline styles, and mermaid renders inline SVG. Removing them is a refactor, not a header change. The policy therefore stays in Report-Only mode. Promote it to an enforcing `Content-Security-Policy` header only after a clean week with no unexpected reports, and keep `'unsafe-inline'` entries until the inline code is refactored.

## 2. Speed settings (Speed, Optimization)

- Brotli: ON
- Early Hints: ON
- HTTP/2 and HTTP/3 (QUIC): ON (Network tab)
- Auto Minify: OFF (CI already minifies `css/style.css` and `js/main.js`; double-minifying is wasted work and can conflict)
- Rocket Loader: OFF (it rewrites script loading and would interfere with the deferred `main.js` and the service worker)

## 3. SSL/TLS

- Encryption mode: Full (strict)
- Edge Certificates: Always Use HTTPS ON, Automatic HTTPS Rewrites ON
- Minimum TLS version: 1.2

## 4. Caching (Caching, Cache Rules)

- Rule `static-assets`: when URI path matches `*.css`, `*.js`, `*.png`, `*.jpg`, `*.jpeg`, `*.webp`, `*.avif`, `*.woff`, then Cache eligibility: Eligible, Edge TTL 1 month, Browser TTL 1 day.
- Rule `html`: when URI path ends in `.html` or is `/`, Edge TTL 2 hours, Browser TTL: Respect origin (short). HTML changes on every deploy, so keep it fresh.
- Do not cache `/api/*.json` longer than 1 hour; the lab and project inventories change.

## 5. www redirect (Rules, Redirect Rules)

Single redirect: when `http.host eq "www.tyfsadik.org"`, 301 to `https://tyfsadik.org${http.request.uri.path}` preserving the query string. Canonical host is the apex.

## 6. Email DNS hardening (self-hosted mail on this domain)

In the DNS tab for `tyfsadik.org`:

1. SPF: `TXT @ "v=spf1 mx -all"` (adjust the mechanism to the real sending hosts before applying `-all`; start with `~all` while verifying).
2. DKIM: publish the selector TXT record generated by the mail server.
3. DMARC: start with `TXT _dmarc "v=DMARC1; p=quarantine; rua=mailto:taki@tyfsadik.org"`, watch reports for two weeks, then move to `p=reject`.
4. MTA-STS: `TXT _mta-sts "v=STSv1; id=<date as yyyymmdd>"` plus an `mta-sts.tyfsadik.org` host serving the policy file (`mode: enforce` once verified).
5. TLS-RPT: `TXT _smtp._tls "v=TLSRPTv1; rua=mailto:taki@tyfsadik.org"`.

## 7. What NOT to change here

- Do not add page rules that strip or append trailing slashes; the site uses `.html` URLs deliberately.
- Do not enable Cloudflare email obfuscation on pages that publish `mailto:taki@tyfsadik.org`; the address is intentionally public and the existing markup works.
- Do not cache `sw.js` at the edge for more than a few minutes; a stale service worker is the one asset that can strand visitors on old content.
